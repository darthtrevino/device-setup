# Windows workstation

Restores a Windows development workstation. Part of [device-setup](../README.md); git, package
feed and VS Code configuration is shared with the macOS and Linux setups from [`../shared`](../shared).

## Layout

```
windows/
├── machine.dsc.winget              # WinGet Configuration (base): apps, Windows settings, WSL, fonts
├── optional/                       # Add-on WinGet Configurations, applied only when wanted
│   ├── visualstudio.dsc.winget     # Visual Studio 2026 Enterprise + workloads
│   ├── visualstudio.vsconfig       # Visual Studio workloads/components consumed by visualstudio.dsc.winget
│   └── physical.dsc.winget         # Physical hardware only (not Dev Box / cloud PCs): Windows App
├── bootstrap.ps1                   # Links the dotfiles below into place + post-install setup
├── powershell-profile.ps1          # -> $PROFILE (PowerShell 7)
├── omp.json                        # -> ~/omp.json (Oh My Posh theme)
├── vscode-extensions.txt           # Windows-only VS Code extensions (on top of the shared list)
└── windows-terminal-settings.json  # -> Windows Terminal settings.json

../shared/                          # installed by bootstrap.ps1, see ../README.md
├── git/gitconfig                   # -> ~/.gitconfig
├── git/auth.ps1                    # gh logins (personal, EMU, GHE.com) + per-remote git routing
├── package-feeds/*                 # copied to the npm/pip/uv/NuGet user config locations
└── vscode/settings.json            # -> %APPDATA%\Code\User\settings.json
```

Personal and org-specific settings are kept **out of this public repo**:

- `~/.gitconfig.local`: git `user.name`/`user.email`, Azure Repos credential blocks, `safe.directory` entries.
- `~/.gitconfig.gh`, `~/.gitconfig.darthtrevino`, `~/.gitconfig.overrides`, `~/.gitconfig.emu`:
  generated by `../shared/git/auth.ps1` (EMU org names, GHE.com host, account logins).
- `~/.vscode-extensions.local.txt` (optional): private/internal VS Code extensions, one ID per line.

## Git identities and GitHub accounts

See [Git identities](../README.md#git-identities-and-github-accounts). Remotes not matched there fall
back to Git Credential Manager, which Git for Windows configures system-wide.

## Rebuilding a workstation

```powershell
git clone https://github.com/darthtrevino/device-setup.git
cd device-setup
winget configure -f windows\machine.dsc.winget --accept-configuration-agreements
# optional add-ons (see below):
winget configure -f windows\optional\visualstudio.dsc.winget --accept-configuration-agreements
winget configure -f windows\optional\physical.dsc.winget --accept-configuration-agreements
# open a new PowerShell 7 terminal, then:
.\windows\bootstrap.ps1
```

The optional configurations are separate files because WinGet Configuration has no conditionals:

- `optional\visualstudio.dsc.winget`: apply when you need full Visual Studio (licensed Enterprise);
  skip it for VS Code-only machines.
- `optional\physical.dsc.winget`: apply only on physical hardware (laptops/desktops); skip it on
  Microsoft Dev Box, cloud PCs, and VMs.

Elevated units (marked 🛡 in winget output) run in a single elevated process, so expect one UAC prompt.
A reboot may be needed afterwards for WSL and Developer Mode.

`bootstrap.ps1` copies the package feed configs, symlinks the dotfiles (existing files are backed up
as `*.<timestamp>.bak`), creates `~/.gitconfig.local` (prompting for name/email if needed), installs
`posh-git`, installs VS Code extensions, and runs `../shared/git/auth.ps1`. Use `-Copy` to copy instead of symlink, `-SkipAuth` to skip GitHub
logins. It is safe to re-run.

To check a machine against the desired state without changing anything:

```powershell
winget configure test -f windows\machine.dsc.winget
winget configure test -f windows\optional\visualstudio.dsc.winget   # if applied
```

## What `machine.dsc.winget` configures

- **Windows settings:** Developer Mode, long path support, dark mode, visible file extensions,
  sudo for Windows, Windows PowerShell execution policy (`RemoteSigned`).
- **Packages:** shell, git, editors (VS Code), AI tooling, language SDKs (including `uv`), CLI
  utilities, cloud/data tools, desktop apps (including PowerToys).
  Framework dependencies, org-managed agents, and Microsoft 365 apps are deliberately excluded;
  see the header comment in the file for the list and how to opt in.
- **WSL** with the Ubuntu distribution.
- **Meslo Nerd Font** for Oh My Posh / Windows Terminal.

### Optional configurations

- **`optional/visualstudio.dsc.winget`:** Visual Studio 2026 Enterprise plus the workloads and
  components from `optional/visualstudio.vsconfig`.
- **`optional/physical.dsc.winget`:** Windows App (remote desktop client for Dev Box / Cloud PC / AVD),
  for physical machines only.

## Updating

```powershell
# Refresh the Visual Studio workload list (run from an elevated prompt)
& "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\setup.exe" export `
  --installPath "C:\Program Files\Microsoft Visual Studio\18\Enterprise" `
  --config windows\optional\visualstudio.vsconfig --quiet

# Find installed packages not yet captured
winget export -o $env:TEMP\apps.json
```
